# Engineering dashboards (draft)

engineering-dashboard.json is a Classic Grafana dashboard proposal (schemaVersion42), with a selectable Prometheus datasource and repository filter. Fifteen panels cover run/CI success, review cycles, lead time, tokens, recorded costs and unknowns, intervention, defects, spending, remediation/deployment failures and source lag. Null/NaN values display Unknown; queries do not turn absent data into zero. USD charges are kept in billing currency, not silently converted into the £5–£10 development target.

metric-contract.json defines each query, unit and denominator. Platform PR #10 now includes an initial producer for CI attempt outcomes, reported input/output tokens and observed source-event counts. The repository selector uses those source-event counts. Other contracts remain proposed metrics. The producer and protected scrape endpoint still need review and deployment plus Grafana collection/remote-write configuration. A valid JSON file does not prove query execution, correct rendering or seeded totals. Do not import this over an existing dashboard or point it at production before review.

Per-issue/model drill-down and cost attribution must use verified trace/run records and avoid unbounded metric labels. Include model filters/breakdowns and issue links once that data pipeline is validated; these drill-downs are not implemented by the fifteen overview panels. Never infer a confirmed defect from every Sentry exception or an actual cost from token counts without reconciled prices. Missing price/usage/billing sources remain Unknown. Provider invoices and ingestion lag can revise spending totals.

Required alert design: stale remediation beyond its approved deadline, CI failure spikes with explicit sample denominator, runaway token/cost usage against owner-approved ceilings, and deployment failures. Thresholds and contact destinations are owner inputs, not inferred from the AWS budget. Configure no-data/error handling as a separate telemetry-health signal so an ingestion outage cannot appear healthy or masquerade as a confirmed deployment failure. Alert routing and test notification remain pending Grafana setup and Mason's chosen channel.

Before KEB-131 is Done: implement the approved metric producer and alert rules, import into a disposable Grafana instance, seed known multi-project/source events and verify totals/filtering/unknowns, inspect desktop/phone layouts, test missing-data/clock/out-of-order behavior, and deliver a test alert to the approved destination. Then repeat against Mason's Cloud stack with restricted credentials and retention limits. No Grafana resources or alerts have been created by this draft.

## Disposable query and layout acceptance

scripts/test_dashboard_runtime.py prepares synthetic OpenMetrics series for fixture/alpha and fixture/beta, backfills them more than3hours in the past into disposable Prometheus, provisions this actual dashboard and queries its expressions through Grafana's datasource proxy. Sixty checks cover all15 panels for each repository, both repositories and an absent repository, including first-attempt denominators, histogram quantiles, partial reported costs and missing-data behavior. These are query-contract fixtures, not evidence that all production metric producers exist. Reported billing totals are explicitly labelled partial because summing known sources does not prove coverage of missing sources.

The required hosted job pins Grafana13.3.0 and Prometheus3.15.1 Linux/amd64 images by registry manifest digest and Playwright1.64.1 plus transitive Python dependencies. Containers use an internal network, read-only roots, unprivileged runner UID, dropped capabilities, no-new-privileges and resource limits. Grafana is exposed only on runner loopback with anonymous Viewer access to synthetic data; no Cloud stack, live credentials, owner data or production datasource is used. The temporary admin password is generated in memory and never used in evidence. Service containers/network are removed before fixture-directory cleanup. These settings are a test fixture, not a production deployment proposal.

After query checks, Playwright captures desktop and390px phone views for each synthetic repository. Query report/screenshots are retained for1day as synthetic-dashboard-evidence. Images must still be inspected; screenshots alone do not establish readable native-phone behavior or alert delivery. The first hosted execution is pending; local evidence currently covers fixture generation, Python syntax, workflow structure and diff checks only because Docker is absent locally. Run the full script only on a disposable Linux/amd64 Docker host with grafana/runtime-requirements.txt and Playwright Chromium installed.

Backfill/provisioning references: https://prometheus.io/docs/prometheus/latest/storage/ and https://grafana.com/docs/grafana/latest/administration/provisioning/ .
