# Engineering dashboards (draft)

engineering-dashboard.json is a Classic Grafana dashboard proposal (schemaVersion 42), with a selectable Prometheus datasource and repository filter. Fifteen panels cover run/CI success, review cycles, lead time, tokens, recorded costs and unknowns, intervention, defects, spending, remediation/deployment failures and source lag. Null/NaN values display Unknown; queries do not turn absent data into zero. USD charges are kept in billing currency, not silently converted into the £5–£10 development target.

metric-contract.json defines each query, unit and denominator. Platform PR #10 now includes initial producers for CI attempt outcomes, reported input/output tokens, observed source-event counts and confirmed review submissions with a separate unclassified counter. The repository selector uses those source-event counts. Other contracts remain proposed metrics. The reviewed producer and protected scrape endpoint still need deployment and Grafana collection/remote-write configuration. A valid JSON file does not prove query execution, correct rendering or seeded totals. Do not import this over an existing dashboard or point it at production before review.

Per-issue/model drill-down and cost attribution must use verified trace/run records and avoid unbounded metric labels. Include model filters/breakdowns and issue links once that data pipeline is validated; these drill-downs are not implemented by the fifteen overview panels. Never infer a confirmed defect from every Sentry exception or an actual cost from token counts without reconciled prices. Missing price/usage/billing sources remain Unknown. Provider invoices and ingestion lag can revise spending totals.

Required alert design: stale remediation beyond its approved deadline, CI failure spikes with explicit sample denominator, runaway token/cost usage against owner-approved ceilings, and deployment failures. Thresholds and contact destinations are owner inputs, not inferred from the AWS budget. Configure no-data/error handling as a separate telemetry-health signal so an ingestion outage cannot appear healthy or masquerade as a confirmed deployment failure. Alert routing and test notification remain pending Grafana setup and Mason's chosen channel.

Before KEB-131 is Done: implement the approved metric producer and alert rules, import into a disposable Grafana instance, seed known multi-project/source events and verify totals/filtering/unknowns, inspect desktop/phone layouts, test missing-data/clock/out-of-order behavior, and deliver a test alert to the approved destination. Then repeat against Mason's Cloud stack with restricted credentials and retention limits. No Grafana resources or alerts have been created by this draft.

## Disposable query and layout acceptance

scripts/test_dashboard_runtime.py prepares synthetic OpenMetrics series for fixture/alpha and fixture/beta, backfills them more than 3 hours in the past into disposable Prometheus, provisions this actual dashboard and queries its expressions through Grafana's datasource proxy. Sixty checks cover all 15 panels for each repository, both repositories and an absent repository, including first-attempt denominators, histogram quantiles, partial reported costs and missing-data behavior. These are query-contract fixtures, not evidence that all production metric producers exist. Reported billing totals are explicitly labelled partial because summing known sources does not prove coverage of missing sources.

The required hosted job pins Grafana 13.3.0 and Prometheus 3.15.1 Linux/amd64 images by registry manifest digest and Playwright 1.64.1 plus transitive Python dependencies. Containers use an internal network, read-only roots, bounded temporary storage, unprivileged runner UID, dropped capabilities, no-new-privileges and resource limits. No ports are published: the Linux runner connects directly to Grafana's private bridge address, with environment proxies disabled. Anonymous Viewer sees synthetic data only; no Cloud stack, live credentials, owner data or production datasource is used. The temporary admin password is generated in memory and never used in evidence. Service containers/network are removed before fixture-directory cleanup. These settings are a test fixture, not a production deployment proposal.

After query checks, Playwright captures desktop and 390 px phone views for each synthetic repository. Query report/screenshots are retained for 1 day as synthetic-dashboard-evidence. Images must still be inspected; screenshots alone do not establish readable native-phone behavior or alert delivery. Hosted run 41348163768 on commit 6696e2c passed all 60 expression checks and native browser assertions for run success, review cycles and input tokens for both repositories on both layouts, with no native query errors. All four screenshots were inspected: values and missing-data Unknown states rendered correctly. Generic regex formatting had escaped repository slashes incorrectly; queries now use datasource-specific Prometheus interpolation. Spending titles were shortened after inspection to keep the partial qualifier visible. Run the full script only on a disposable Linux/amd64 Docker host with grafana/runtime-requirements.txt and Playwright Chromium installed.

## Configurable alert rules

See [alerts.md](alerts.md) for explicit threshold configuration, separate missing-data signals, native promtool fixtures and remaining Cloud routing acceptance. The builder generates data source rules without deploying them; no owner thresholds are guessed.

Review cycles are labelled partial: explicit decisions and authenticated inline-review evidence count, while body-only/rate-limit/ambiguous submissions remain unclassified in agentic_review_unclassified_total. Production provider classification and delivery reconciliation remain required; no complete-coverage claim follows from confirmed counters.

Source delivery lag measures the latest durable receipt minus its source timestamp. It does not grow while a source is quiet: use the separate receipt-age gauge and approved heartbeat policy for freshness. Invalid/legacy timing is exposed by source_timing_valid and a separate timing-health alert; no source clock is assumed correct. The current producer and native rule fixture cover these signals, but Cloud collection and actual clock reconciliation are unverified.

## Ingestion-to-dashboard fixture

The dashboard branch now includes the merged telemetry library. `scripts/dashboard_producer_fixture.py` sends synthetic signed GitHub workflow/review and Linear issue requests through the real WSGI factory, signature/installation/issue mapping checks and file-backed EventStore. Synthetic Codex terminal usage goes through the real normalization adapter. A protected metrics WSGI scrape uses the real projection. Only provider payloads, fixture credentials, review-comment evidence and receiver/scrape clocks are controlled. No coding model, provider account or live ingestion endpoint is called.

The current fixture generates 61 minute snapshots and 6,310 durable events across two repositories. Duplicate signed deliveries do not inflate totals; three invalid-auth checks leave the store empty; 70 final counter/timing/histogram samples and absence of private fixture text are asserted. These measured exposition samples backfill disposable Prometheus. Six overview panels are producer-backed: CI first-pass success, confirmed review cycles, observed issue-to-merge p50, input/output tokens and source delivery lag. Browser checks assert all six plus the run-success query-contract panel in both layouts/repositories. Native runtime acceptance of the new lead-time path is pending.

Nine remaining panels still use explicitly synthetic query-contract series because their producer requirements are not implemented. The evidence report lists producer_backed_panels and contract_only_panels; do not claim fifteen production producers or live four-source acceptance. This fixture does not export to Cloud or exercise production TLS, App authentication, retention, alert routing or actual source clock synchronization. The database is fresh, fixture-only, owner-readable and never uploaded as an artifact. Only counts and derived query/render evidence are retained.

`--generate-only` can verify fixture generation on a fresh disposable output directory without Docker. Complete runtime acceptance still requires the pinned Linux Docker images and browser. Hosted run 41354680429 on edbfdf5 passed the combined producer-to-Grafana fixture: 5,350 events, 38 final producer samples, 60 dashboard queries, 24 browser value assertions across four layout/repository cases, nine native rule scenarios and the merged telemetry suite of 62 tests. All four screenshots were inspected and rendered values/Unknown states were correct. This is synthetic integration evidence, not live Cloud or notification acceptance.

Run success and lead-time p50 summarize completions across the selected dashboard range. Their instant queries use increase over $__range. The query-contract fixture now places those completions in the first 20 minutes and has a quiet final 40 minutes: one-hour totals remain known, while four explicit five-minute queries must return Unknown. This catches a recent-rate window incorrectly replacing the selected range.

The observed lead-time producer, source timestamp boundaries, incomplete-data gauge and required reconciliation behavior are documented in [docs/lead-time.md](../docs/lead-time.md). The partial label is intentional: newly joined observations may arrive after their source merge time. The one-hour and quiet-tail regressions now exercise its real signed-ingestion/projection path rather than hand-authored histogram series.
